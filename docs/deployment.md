# Django deployment on Render

The root `render.yaml` deploys `main` as a public Python web service with a
PostgreSQL database in Frankfurt. Django authentication continues to protect
the workspace. No demo accounts or data are created automatically.

## Deploy

1. Open https://dashboard.render.com/select-repo?type=blueprint and select
   `abems123/HackathonWinners` (branch `main`).
2. Review the web service and database plans, then apply the Blueprint.
3. Wait for a successful deployment and open the service's `.onrender.com` URL.

The free web service sleeps when idle, and the free database expires after 30
days. Upgrade the database before expiry if the app must retain its data. For
an always-on deployment, choose paid plans in Render. The committed Blueprint
does not select paid resources.

## Commands and environment

- Build: `bash build.sh` installs requirements and collects static assets.
- Start: `bash start.sh` applies migrations and starts Gunicorn on `$PORT`.
- `DJANGO_SECRET_KEY` is generated by Render; do not commit it.
- `DATABASE_URL` comes from the Blueprint database.
- `DJANGO_DEBUG=False` enables the existing HTTPS and secure-cookie settings.
- The Render hostname is allowed automatically. For a custom domain, add its
  hostname to `DJANGO_ALLOWED_HOSTS` and its HTTPS origin to
  `DJANGO_CSRF_TRUSTED_ORIGINS` (comma-separated lists).
- `AI_MODE=cache` preserves the current offline mode without AI credentials.

## First account

The application requires login and has no public signup. Create an administrator
using `python manage.py createsuperuser` in a Render shell when available, or
from a trusted local machine with the deployed database connection and a local
secret configured. Keep database credentials out of shell history and Git.
Do not run the demo `seed` command against a database containing real data;
it creates accounts with publicly documented passwords.

Migrations run at startup because free services do not support pre-deploy
commands. When moving to paid services or multiple instances, run migrations
once as a pre-deploy command and start Gunicorn directly.
